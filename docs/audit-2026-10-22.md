## 三、已修复（P1）

### P1-1 KPI 数字滚动出现负值

- **位置**：`client/src/composables/useCountUp.ts`
- **现象**：打开数据看板的前 200ms 内，KPI 会闪现 `-2 件`、`-3 笔`、`-2231.02 元` 这类负值。
- **复现**：以 admin 进入 `/dashboard`，在 250ms 内读取 `.kpi-value` 文本即可抓到 `-3 件`、`-2231.02 元`。
- **根因**：`progress` 只做了上限钳制。`requestAnimationFrame` 回调参数是**该帧开始时刻**，可能早于推进动画时记录的 `performance.now()`，于是 `progress` 为负；`easeOutCubic(负数)` 会得到绝对值很大的负数，插值结果直接掉到 0 以下。
- **修复**：`Math.min(Math.max((now - start) / duration, 0), 1)`。
- **验证**：修复前采样序列含负值（`kpiHasNegative: true`）；修复后首个动画帧为 `0 人|0 件|0 笔|0.00 元`，`kpiHasNegative: false`，仍有 33 个不同中间帧，滚动效果未受影响。

### P1-2 数据库故障时把服务器绝对路径返回给前端

- **位置**：`server/src/middleware/errorHandler.ts`、`server/src/controllers/ai.controller.ts`
- **现象**：数据库不可用时，接口返回 `message` 里带完整调用栈片段与绝对路径，例如
  ``Invalid `prisma.product.count()` invocation in F:\二手app\...\product.service.ts:114:20``，
  前端会把这段原文直接显示在 toast 里。演示模式 `NODE_ENV=development` 时一定会命中。
- **复现**：停掉数据库后请求 `/api/products`。
- **根因**：`PrismaClientInitializationError` 等初始化类错误不在 `PrismaClientKnownRequestError` 分支内，落到了「未预期异常」兜底，开发模式下回显 `err.message`；同时 `P1001` 连接错误被归到「参数错误」返回 400，语义也不对。
- **修复**：
  1. 新增初始化/运行时类 Prisma 错误分支 → 503 + 统一文案；
  2. 连接类错误码（P1000/P1001/P1002/P1003/P1008/P1010/P1017/P2024）→ 503 + 统一文案；
  3. 兜底分支对开发模式的 message 做绝对路径脱敏；
  4. SSE 流（不走统一中间件）复用同一套脱敏函数，避免错误通过 `event: error` 泄漏。
- **验证**：停库后 `/api/products`、`/api/categories` 均返回
  `HTTP 503 {"code":50000,"message":"数据库暂时不可用（请确认 MySQL 已启动且 DATABASE_URL 正确）","data":null}`，
  不再包含路径或 Prisma 调用细节。

### P1-3 含品类词的自然查询全部 0 结果（含 UI 自己建议的追问句）

- **位置**：`server/src/services/searchSynonyms.ts`、`server/src/services/aiChat.service.ts`
- **现象**：

  | 用户输入 | 修复前 |
  | --- | --- |
  | `2000以内的手机` | **0 条** |
  | `换成电脑` | **0 条** |
  | `换成手机数码看看`（AI 助手自己给出的建议词） | **0 条** |
  | `还有别的推荐吗` | **0 条** |
  | `只看全新的` | **0 条** |

- **根因**：规则解析把「手机 / 电脑 / 数码」当作关键词保留，而这些字眼在商品标题里从不出现（标题写的是 `iPhone 13`、`MacBook Air`），于是「分类条件已经圈定范围」与「关键词再匹配一次」互相矛盾，把自己过滤成空集。追加一句「还有别的推荐吗」时，还会残留单字碎片（`还有别 推荐` → 剥离停用词后只剩 `别`），同样把结果清空。
- **修复**：
  1. 新增 `CATEGORY_ONLY_WORDS`：纯品类词只用于选分类，不再作为关键词；
  2. 剥离停用词后若只剩单字残片（无 2 字以上中文、无 2 位以上字母数字），视为「无关键词」；
  3. 「已识别条件」文案与真实检索保持一致，不再展示被丢弃的关键词。
- **验证**（AI_MOCK 与真实 AI 两条路径均通过）：

  | 输入 | 修复后 |
  | --- | --- |
  | `2000以内的手机` | 3 条（AirPods Pro 2 / iPhone 13 / 小米 13） |
  | `换成电脑` | 6 条 |
  | `换成手机数码看看` | 4 条 |
  | `还有别的推荐吗` | 13 条（全部在售，符合「再推荐一些」的意图） |
  | `只看全新的` | 1 条 |
  | `有没有苹果手机` | 1 条（iPhone 13，品牌别名展开仍生效） |
  | `两千以内` | 9~10 条 |

## 四、排除的疑似问题（实测确认不是缺陷）

| # | 初筛疑点 | 结论 |
| --- | --- | --- |
| 1 | `localStorage` 的 `JSON.parse` 未加保护会白屏 | **误报**。`cart.ts` / `auth.ts` / `currentUser.ts` / `aiChat.ts` 全部有 `try/catch` 并回退到安全默认值，注入坏数据实测无异常 |
| 2 | 订单状态机并发竞态（文档自述） | **未复现**。并发两次「付款」得到 `200 / 403`：第二请求在状态机重新校验时被正确拒绝，未出现重复流转。事务内的 `updateMany + status:'ON_SALE'` 乐观锁也挡住了「一物多卖」 |
| 3 | 上传只要声明 `image/png` 就能存 HTML | **有兜底**。服务端按声明的 MIME 白名单放行（`text/html`、`application/pdf` 均 400），存下来的文件由 `/uploads` 静态响应附带 `X-Content-Type-Options: nosniff` + `Content-Security-Policy: default-src 'none'; sandbox`，浏览器不会执行。属于「设计取舍 + 补偿控制」，非缺陷 |
| 4 | ECharts 入场动画没生效 | **误判**。首次采样区域过小导致只取到空白像素。改用整幅 canvas 采样后：`no-preference` 下 28 个不同帧、跨度 469ms；`reduce` 下只有 1 帧 —— 动画正常，且 reduced-motion 降级有效 |
